## W-01: イベント一覧（トップページ）

### 全体の構造

主に PC の画面幅を想定する（[Q1]=B）。スマートフォンでも読めることを最低限とする。

### 1件の構成

各イベントは独立した枠（カード）として表示する。含める項目は次のとおり。

| 行 | 内容 | 根拠 |
|---|---|---|
| 1 | イベントのタイトル。connpass のイベントページへのリンクになる | scope-document（詳細は connpass へリンク）、[Q2] |
| 2 | 開催日時（開始 - 終了） | scope-document |
| 3 | 開催場所 | scope-document |
| 4 | 県名バッジ、定員と参加者数、ハッシュタグ | [Q2]=A, B, C |

主催者名は載せない（C-14）。概要文も載せない（[Q2] で D は選択されなかった）。

定員と参加者数は「参加者数 / 定員」の形で示す。ハッシュタグは取得できたものだけ表示し、なければその箇所を空ける。

### エリアの区別

「福井」と「石川・富山」を別の見出しで分け、福井を先に置く（[Q5] of scope-definition=B、C-11）。

加えて各イベントに県名バッジを付ける（[Q2]=A）。見出しだけでも区別は付くが、「石川・富山」の節では石川と富山が混在するため、バッジがないと1件ごとの県が分からない。また色だけに頼らない表現という要件（[Q7]=A）を満たすため、バッジは文字で県名を示す。

### 終了したイベントの扱い

一覧の下部に「終了したイベント」という見出しでまとめる（[Q3]=A）。これから開催されるものと混在させない。

終了したイベントにも「終了」の表示を付ける。見出しで分けているため冗長に見えるが、スクロール位置によっては見出しが画面外にあり、どの節を見ているか分からなくなるためである。

### 画面の状態

低精細の段階だが、5つの状態すべてを定義する。

#### 1. 通常状態（イベントあり）

上記の構造のとおり。

#### 2. 空状態（該当期間にイベントが0件）

```
+----------------------------------------------------------+
| header                                                   |
|  北陸ITイベント                                     (h1) |
|  福井・石川・富山で開催されるオフラインのIT勉強会        |
+----------------------------------------------------------+
| main                                                     |
|                                                          |
|   該当する期間に開催されるイベントはありません。         |
|                                                          |
+----------------------------------------------------------+
| footer                                                   |
|  最終収集: 2026-09-20 06:00                              |
|  イベント情報の提供元: connpass                          |
+----------------------------------------------------------+
```

<!-- Text fallback: ヘッダーとフッターは通常状態と同じ。本文には「該当する期間に開催されるイベントはありません。」という一文のみが表示される。フッターの最終収集日時は常に表示されるため、収集が動いているのに0件なのか、収集自体が止まっているのかを読み手が区別できる。 -->

「該当する期間にイベントはありません」と明示し、最終収集日時も併せて出す（[Q5]=A）。真っ白な画面では「壊れている」のか「本当にない」のかが区別できないためである。フッターの最終収集日時が新しければ、収集は動いていて本当に0件だと分かる。

北陸3県のIT勉強会は時期によって数週間なにもないことがあり得るため、この状態は例外ではなく通常運用の一部として扱う。

#### 3. 読み込み中の状態

保存済みのデータを表示する画面であり、外部への問い合わせを伴わない。読み込み中の状態を専用に設計する必要はない。実装方式によっては瞬間的に生じうるが、その場合も通常のページ読み込みとして扱う。

#### 4. エラー状態

イベントの取得元は自分のデータ保存先であり、ページ生成時点で参照できる前提である。それでも表示できない事態が起きた場合は、原因を示さず「現在イベントを表示できません」とだけ伝える。生の技術的エラーは表示しない。

**このとき最終収集日時も表示しない。** イベントと最終収集日時は同じ保存先から読むため、イベントが読めない状況では日時も読めない。両者に別々の取得経路を用意する設計にはしない。したがってエラー状態の画面はヘッダーと「現在イベントを表示できません」の一文のみとなり、フッターには情報の提供元（connpass）だけが残る。

#### 5. 端の状態

| 状況 | 扱い |
|---|---|
| タイトルが非常に長い | 枠の中で折り返す。省略記号で切らない（切ると内容が分からなくなる） |
| 開催場所が未設定 | その行を空ける。「場所未定」などの補いは入れない（connpass 側の登録状態をそのまま反映する） |
| 定員が未設定 | 参加者数のみを表示する |
| ハッシュタグがない | その箇所を空ける |
| 石川・富山が0件で福井のみある | 「石川・富山」の見出しごと出さない |
| 福井が0件で石川・富山のみある | 「福井」の見出しは出し、その下に該当がない旨の一文を置く。見出しごと消さない |
| 終了したイベントが0件 | 「終了したイベント」の見出しごと出さない |
| これから開催されるものが3県とも0件で、終了したイベントだけがある | 「福井」「石川・富山」の見出しは出さず、「終了したイベント」の節だけを出す。空状態には倒さない |
| これからも0件、終了したものも0件 | 空状態（上記2）に倒す |

福井と石川・富山で扱いを変えるのは意図的である。福井は主対象であり（C-11）、見出しが消えると「福井の情報を集めていない」のか「たまたま0件」なのかが読み手に区別できない。石川・富山は副次的な対象なので、0件なら見出しごと省いて一覧を短くしてよい。

### 最終収集日時の表示

フッターに「最終収集: YYYY-MM-DD HH:MM」の形で表示する（[Q4]=A）。目立たせない。

これは scope-document の S-05「収集が止まったことに気づける」の一部を画面で担うものである。開いた瞬間に鮮度が分かり、収集が止まっていれば日付が古いまま残るため、本人が気づく手がかりになる。閲覧者にとっても情報の新しさの判断材料になる。

ただしこれだけでは S-05 を満たさない。画面を見に行かなければ気づけないためである。画面の外での検知手段（記録や通知）は NFR Requirements と observability-setup で確定する。

「しばらく更新されていない場合に警告を出す」という選択肢（[Q4] の B）は選ばれなかったため、警告表示は作らない。

### アクセシビリティ

基本を押さえる水準とする（[Q7]=A）。WCAG 2.1 AA を明示的な目標としては掲げない。

| 項目 | 方針 |
|---|---|
| 見出し構造 | h1 はサイト名（ページに1つ）。h2 は「福井」「石川・富山」「終了したイベント」。h3 は各イベントのタイトル。階層を飛ばさない |
| ランドマーク | `header`、`main`、`footer` を用いる。ナビゲーションがないため `nav` は使わない |
| キーボード操作 | 操作対象はイベントタイトルのリンクのみ。上から順に辿れるようにし、フォーカスが見えるようにする |
| 色だけに頼らない | 県名バッジは文字で県名を示す。終了したイベントは文字の薄さだけでなく「終了」の表示でも区別する |
| 代替テキスト | 画像を使わない設計のため、現時点で対象がない。将来画像を加える場合は代替テキストを付ける |
| 言語 | 日本語を宣言する |

操作要素がリンクだけで、フォームもモーダルもタブもないため、アクセシビリティ上の難所は少ない。

### 見た目の方針

ある程度は見栄えを整える（[Q6]=C）。配色とカードのような区切りを入れる。ただし装飾のための装飾は入れない。

具体的な配色・字形・余白の値は定めない。Refined Mockups を実行しないため、実装時に決めることになる。その際の判断基準は次の2点とする。

- 一覧としての走査しやすさを最優先する。1件が縦に伸びすぎない
- 県名バッジと「終了」の表示は、色を変えるだけでなく文字でも区別が付く

## W-02: 個人用 RSS フィード

画面ではなくフィードである。RSS リーダーで読むことを前提とし、ブラウザで開いたときの見た目は設計対象としない。

認証付きで本人専用とする（C-13）。一般公開しない。認証方式（URL にトークンを埋め込む方式か HTTP Basic 認証か）は Functional Design で確定する（feasibility A-06）。

1件あたりに含める内容は W-01 の1件の構成に準じる。リンク先は connpass のイベントページとする。

配信する範囲（福井のみか3県すべてか）は未確定である（scope-document の未確定事項）。

W-01 は一般公開、W-02 は本人専用であり、**公開ページから RSS への導線は置かない**。導線を置くと本人専用である意味が失われるためである。

## Assumptions & Open Questions

- 「直近1〜2週間」の具体的な日数は未確定。W-01 の「終了したイベント」に何件並ぶかがこれで変わる。Functional Design で確定する [assumption]
- W-02 の配信範囲（福井のみか3県すべてか）は未確定 [assumption]
- W-02 の認証方式は未確定。Functional Design で確定する [assumption]
- 「これから開催されるもの」の判定に開催日と申込期限のどちらを使うかは未確定。W-01 のどの節に置かれるかがこれで変わる [assumption]
- 配色・字形・余白の具体値は未確定。Refined Mockups を実行しないため、実装時に上記の判断基準に沿って決める [assumption]
- ハッシュタグを表示する際、connpass のハッシュタグ検索へリンクするかどうかは未確定 [assumption]
- 1ページに何件まで表示するか（件数が非常に多い場合の扱い）は未確定。北陸3県かつ期間限定のため通常は問題にならないと見込むが、確認していない [assumption]
