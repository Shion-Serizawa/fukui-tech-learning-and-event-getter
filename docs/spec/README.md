## 検証手段の種類

03-behavior.md の各要件には、次のいずれかの検証手段を付ける。

| 記号       | 意味                                                                                                      |
| ---------- | --------------------------------------------------------------------------------------------------------- |
| **test**   | 自動テストが要件 ID を名前に含む（`describe("WEB-08: ...")` など）。`npm run spec:check` が対応を検査する |
| **lint**   | `tools/lint/` のルールか oxlint の組み込みルールが、違反するコードを止める                                |
| **type**   | 型の定義が、違反するコードをコンパイルさせない                                                            |
| **config** | 設定ファイル（`wrangler.jsonc`、`web/public/_headers` など）で決まる                                      |
| **実測**   | 自動では確かめられない。本番の観測か、手作業（`V-nn`）で確かめる                                          |

## 仕様を変えるとき

1. この仕様書を先に変える。コードだけ変えて仕様書を後追いにしない
2. 要件を足したら ID を振り、検証手段を決める。**test なら同じ PR でテストを足す**
3. 規則を足したら、05-architecture.md の「規則と強制手段」に行を足す。**文章でしか守れない規則は、決定的な検査（lint・型・テスト）に落とせないかを先に考える**
4. 迷ったら 01-product.md の「作らないもの」と「制約」を見る
