# 06. 運用

## 環境

本番ひとつ（Q9=A）。ステージング環境は作らない。承認の仕組みは「PR の CI」と「骨格の受け入れ確認」が担う。

## ローカル開発

### 準備（初回だけ）

```sh
mise install                       # Node（mise.toml で固定）
npm ci
cp .dev.vars.example .dev.vars     # 値を入れる。コミットしない
npm run db:migrate:local           # 手元の D1（.wrangler/state）にテーブルを作る
```

### 収集から公開ページまでを手元で動かす

端末を2つ使う。Worker と web（Pages）は**同じ手元の D1**（`.wrangler/state`）を読み書きする。

```sh
# 端末1: Worker（収集）。http://localhost:8787 は 404 しか返さない（本番と同じ）
npm run dev

# 端末2: web（公開一覧と RSS）
npm run dev:web
#   → ブラウザで http://localhost:8788/ と http://localhost:8788/feed.xml を開く

# 端末2（または3）: 収集を1回起動する
npm run collect:local
#   → 端末1に {"event":"connpass.request",...} のログが出る。数秒後に web を再読み込みすると一覧に出る
```

- `npm run collect:local` は `.dev.vars` のキーで**本物の connpass API を呼ぶ**（1回の収集で3県分の3リクエスト、13秒間隔なので30秒ほどかかる）。**本番と同じキーなので、1日100回（C-04）を本番と分け合う。**本番は1日24回使うので、手元で使えるのは1日あと十数回の収集まで。連打しない。本番の起動時刻（JST の 0・3・6…時の17分）の前後数分も避ける（同じキーで12秒以内に重なると 429 になる）。日常の確認は自動テスト（偽の fetch + フィクスチャ。外部通信は遮断されている）で行う
- `.dev.vars` に `DISCORD_WEBHOOK_URL` が入っていると、手元でも停止通知・復旧通知が本物の Discord に送られる。手元で収集が一度も成功していない状態（停止中）で起動すると、停止通知が1通届く。避けたいときは手元ではその行を空にする
- 手元のデータを消したいときは `.wrangler/state` を消して、`npm run db:migrate:local` からやり直す
- `npm run check` は型・lint・整形・テスト（カバレッジ込み）・仕様との対応をまとめて検査する。PR を出す前に通す

### 本番の Cron を手で動かすことはできない

本番には手動で起動する手段がない。Cron の時刻を一時的にずらす方法は、**Cron の変更が反映されるまで最大15分かかり、その間の起動は飛ばされる**ため使えない（2026-11-23 に試して確認）。手で確かめたいときは上の手順で手元で動かす。

## シークレット

値は書かない。名前だけを書く。

| 名前                    | 置き場所                                                               | 用途                                                                                                                                |
| ----------------------- | ---------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `CONNPASS_API_KEY`      | Worker のシークレット（`wrangler secret put`）、ローカルは `.dev.vars` | connpass API の認証（C-03）。**1つしか発行されず、漏れても自分で再発行できない**ので厚く守る                                        |
| `DISCORD_WEBHOOK_URL`   | Worker のシークレット、ローカルは `.dev.vars`（空なら送らない）        | 停止・復旧の通知（HLT-05）。URL を知っていれば誰でも投稿できるので、値をどこにも書かない。漏れたら Discord 側で Webhook を作り直す  |

`wrangler.jsonc` の `vars` は平文の設定であってシークレットではない。シークレットを `vars` に書かない。

## CI

`.github/workflows/ci.yml`。PR と `main` への push で動く。

| ジョブ                           | 止めるか | 内容                                                                                                         |
| -------------------------------- | -------- | ------------------------------------------------------------------------------------------------------------ |
| 型・リント・整形・テスト・ビルド | 止める   | `typecheck` → `lint` → `fmt:check` → `types:check` → `test:coverage`（行 80%）→ `spec:check` → `build:check` |
| シークレット検出                 | 止める   | gitleaks（履歴全体）                                                                                         |
| 依存の脆弱性                     | 表示のみ | `npm audit`                                                                                                  |

止めるものを絞るのは意図的。単独開発でゲートを増やすと、止まった理由が本物かを毎回1人で判断することになり、閾値をいじって黙らせる習慣がつく。

## デプロイ

`.github/workflows/deploy.yml`。`main` への push でだけ動く（`pull_request` では動かない）。

1. `npm ci` → `npm run check`（デプロイ前にもう一度検査する）
2. D1 マイグレーション（`wrangler d1 migrations apply --remote`）。スキーマ変更は列の追加のみなので、コードより先に適用してよい
3. Worker（`wrangler deploy`）
4. Pages（`wrangler pages deploy --cwd web`）
5. 確認: 公開ページに「最終収集」が出ること、`/feed.xml` が RSS を返すこと

Cloudflare の API トークンは手順 2〜4 のステップにだけ渡す。`npm ci` やテストには渡さない（依存パッケージのスクリプトからトークンを読まれる経路を作らない）。

### 初回だけ手で行うこと（Cloudflare・Discord・GitHub）

- [x] D1 を作る（2026-11-23、置き場所の目安 `apac`）。`database_id` は `wrangler.jsonc` と `web/wrangler.jsonc` に記入済み（ID はシークレットではない）。マイグレーションは初回デプロイで適用される
- [x] Pages のプロジェクトを作る（2026-11-23、直接アップロード方式、本番ブランチ `main`、`https://hokuriku-it-events.pages.dev`）
- [ ] Worker のシークレットを入れる: `wrangler secret put CONNPASS_API_KEY`、`wrangler secret put DISCORD_WEBHOOK_URL`
- [ ] Discord で通知先チャンネルの Webhook を作る（本人だけが見るチャンネル）
- [ ] Cloudflare のスコープ付き API トークンを作る（Workers Scripts:Edit / D1:Edit / Cloudflare Pages:Edit、対象アカウントのみ）。**Global API Key は使わない**
- [ ] GitHub の Environment `production` にシークレット `CLOUDFLARE_API_TOKEN` を入れる（変数 `CLOUDFLARE_ACCOUNT_ID` と `PUBLIC_SITE_URL` は設定済み）
- [x] Environment `production` の Deployment branches を `main` だけに限定する（ほかのブランチのワークフローからトークンを使わせない）

### デプロイ後の確認

- 公開ページが 200 を返し、フッターに最終収集日時が出る（WEB-10）。初回は「まだありません」
- Cron は次の起動（JST の 0・3・6…時の17分）を待つ必要がある。次の起動の後に最終収集日時が更新されることを見る
- 収集が3回続けて失敗すると（最後の成功から約9時間後）、Discord に停止通知が届く（HLT-02）

## アカウントの保険（課金とセキュリティ）

**課金されない理由は「Workers Free プランのまま使う」ことにある。** Free プランの上限は打ち切り型で、超えると Worker はエラー（1027）、D1 はクエリが失敗するだけで、請求は発生しない（D1 は上限到達時にメールが届く）。Workers Paid（月 $5〜）に上げたときだけ従量課金が始まる。

| 設定                                           | 状態                       | 備考                                                                                                              |
| ---------------------------------------------- | -------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| 予算アラート（従量課金が $1 を超えたらメール） | 設定済み（2026-11-23）     | 通知のみ。Free のままなら発火しない。発火したら何かが有料になっている                                             |
| 不正利用（abuse）通報のメール通知              | 設定済み（2026-11-23）     | —                                                                                                                 |
| Workers Paid にしない・支払い方法を登録しない  | 運用ルール                 | 上げる場合は先に Workers の spending limit（支出上限）を設定する                                                  |
| ログインの二要素認証                           | 設定済み（2026-11-23）     | ダッシュボードの My Profile → Authentication。アカウントを乗っ取られると、Worker の書き換えや有料化ができてしまう |
| Pages のデプロイ失敗の通知                     | 設定済み（2026-11-23）     | 通知の種類 `pages_event_alert`                                                                                    |
| デプロイ用 API トークンの有効期限              | トークン発行時に設定       | 1年程度を目安に期限を付け、切れる前に作り直す                                                                     |
| Claude の MCP 接続（OAuth）の権限              | 初期設定が終わったら見直す | My Profile から接続済みアプリの権限を確認し、不要なら取り消す                                                     |

## 無料枠の見積もり（C-09）

無料枠は**1回の起動あたり**の上限が厳しい。収集の実装はこれに合わせてある。

| 上限（Workers Free / D1 Free）    | 本件の使い方                                                                            | 余裕                                                                                                                       |
| --------------------------------- | --------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 1回の起動あたりの D1 クエリ数     | 収集1回: 書き込みのバッチ1つ（5文）+ 健全性の確認（4文程度）。表示1回: バッチ1つ（2文） | イベントを1件ずつ upsert すると上限に当たるので、JSON の1パラメータ + `json_each` で1文にまとめている（`src/db/write.ts`） |
| 1回の起動あたりのサブリクエスト数 | connpass 3〜数リクエスト（最大 30）+ Discord 0〜1                                       | 十分                                                                                                                       |
| 1回の起動あたりの CPU 時間        | 待機（13秒 × 2回）は CPU 時間に数えない。JSON の解析と検証が数百件分                    | **実測で確認する**（デプロイ後に Workers のログで CPU 時間を見る）                                                         |
| 1日あたりのリクエスト数           | Cron 24回 + 公開ページ・RSS のアクセス                                                  | 十分                                                                                                                       |
| D1 の容量                         | 30日より古いものを消す（STO-06）ので数千行程度                                          | 十分                                                                                                                       |

具体的な上限値は Cloudflare の公式ドキュメントで確認すること（変わることがある）。構成を変えるときはこの表を更新する。

## 実レスポンスとの突き合わせ（V-nn）

**API キーは発行済み。実装の最初（骨格の着手前）にこれを行う。** 自動テストからではなく**手で1回だけ**実レスポンスを取得し、次を確かめる。取得した生のレスポンスはリポジトリの外（例: `/tmp`）に置き、確認が済んだら消す（主催者名が含まれるため）。

```sh
# 例: 福井・今月分を1回だけ。キーはシェルの履歴に残さないよう .dev.vars から読む
set -a; . ./.dev.vars; set +a
curl -sS -H "X-API-Key: $CONNPASS_API_KEY" \
  "https://connpass.com/api/v2/events/?prefecture=fukui&ym=$(date +%Y%m)&count=100" > /tmp/connpass-sample.json
```

## M-02 の測り方

D1 に対して（`wrangler d1 execute hokuriku-it-events --remote --command "..."`）:

```sql
SELECT
  COUNT(*) AS total,
  SUM(CASE WHEN first_seen_at < started_at THEN 1 ELSE 0 END) AS delivered_before_start
FROM events
WHERE ended_at <= :now AND ended_at > :now - 14 * 24 * 60 * 60 * 1000;
```

`delivered_before_start / total` が 100% であること。
