# 01. プロダクト

## 一行でいうと

**北陸（福井・石川・富山）で開催されるオフラインの IT イベントを connpass から定期的に集め、公開ページで一覧でき、新着を RSS で受け取れて、集まらなくなったら Discord で気づける状態にする。**

## 解決する問題

北陸の IT イベント・勉強会の情報は複数のサイトに散らばっている。困りごとは2つの側面を持つ。

| 側面       | 内容                                                                                           |
| ---------- | ---------------------------------------------------------------------------------------------- |
| 探索コスト | 探すたびに同じ検索手順を繰り返す。福井開催のものだけを絞り込みにくく、他県のイベントに埋もれる |
| 機会損失   | 探索が間に合わず、申込期限や開催日を過ぎてから気づく。実際に見逃した経験が着手のきっかけ       |

## 利用者

| 利用者                         | 使うもの                                          | 位置づけ                                   |
| ------------------------------ | ------------------------------------------------- | ------------------------------------------ |
| 本人                           | 公開ページ（F-01）、RSS（F-02）、停止通知（F-04） | 主な利用者。基準は本人の使い勝手に置く     |
| 北陸の IT コミュニティの閲覧者 | 公開ページ（F-01）、RSS（F-02）                   | 副次的な読み手。内容が分かる程度には整える |

利用者登録・ログインは作らない。

## 成功の基準

| ID   | 指標                                                                     | 測り方                                                                        | 対応する側面     |
| ---- | ------------------------------------------------------------------------ | ----------------------------------------------------------------------------- | ---------------- |
| M-01 | 福井の IT 勉強会を探すために、収集元サイトを直接巡回する回数がゼロになる | 本人の実感（定性）                                                            | 探索コスト       |
| M-02 | 開催日より前に RSS へ配信されたイベントの割合が 100%                     | `first_seen_at < started_at` を満たすイベントの割合（03-behavior.md「M-02」） | 機会損失（D-41） |

M-02 は「RSS に配信されれば気づける」という判断を測れる形にしたもの。見逃しの原因を「RSS に載らなかった」と「載ったが読まなかった」に分けられる。

## 作るもの（最初のバージョン）

5つが揃って初めて成功の基準を満たす。どれか1つを落とすと、どちらかの側面が欠ける。

| 機能                     | 内容                                                                     | 要件  |
| ------------------------ | ------------------------------------------------------------------------ | ----- |
| 収集（F-03）             | connpass API から北陸3県のイベントを1時間に1回取得する                   | COL-* |
| 保存                     | 重複を除いて最新の状態を保つ                                             | STO-* |
| 公開イベント一覧（F-01） | これから開催されるものと直近14日に終了したものを、福井を先にして一覧する | WEB-* |
| RSS（F-02）              | 新着を配信する。認証なしの公開                                           | RSS-* |
| 収集の健全性（F-04）     | 収集が止まったら Discord に通知し、本人が気づける                        | HLT-* |

作る順番（D-35）: **収集 + 保存（骨格。Cloudflare 上で動くところまで）→ 健全性 → 公開一覧 → RSS**。connpass からの取得が唯一こちらで評価できない不確実性なので、最初に端から端まで通す。

## 作らないもの

後から迷わないための線引き。将来の再検討は妨げない。

- キーワード検索、開催日・エリアでの絞り込み、並び替え
- 終了したイベントを遡って閲覧する機能（直近14日の終了分は一覧に出る。これは一覧の既定の対象期間であって、遡る操作手段ではない）
- 利用者登録・ログイン、イベントへの申込み（connpass へリンクする）、お気に入り・参加予定の管理
- 自分以外への通知（メール配信など）、スマートフォンアプリ
- イベントの詳細ページ（connpass へリンクする）
- 公開ページでの「更新が途絶えている」警告（D-25。最終収集日時を出すだけ）
- connpass 側のリンク先が生きているかの確認（D-33。レート制限と規約の両面で割に合わない）
- 負荷テスト（利用者1名、収集1時間に1回、無料枠の上限にも遠い）

## 従う制約

違反すると規約違反・費用発生・個人情報の扱いの問題になるもの。出典の ID は AI-DLC 側の `constraint-register.md` / `decision-log.md`。

### connpass の規約

| ID   | 制約                                                                                                                                           |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| C-01 | connpass からの取得は**公式 API v2 経由のみ**。スクレイピング・クローリングその他の方法は、自動・手動を問わず禁止（利用規約 第7条第1項第17号） |
| C-02 | API キーは申請・審査を経て1つだけ発行される。**発行済み（2026-11 時点）**。1つしかなく自分で再発行できないので厚く守る                         |
| C-03 | 認証は `X-API-Key` ヘッダ。キーはソースに書かずシークレットとして管理する                                                                      |
| C-04 | レート制限は API キーあたり 1秒1リクエスト（利用報告による。公式リファレンスで確認する → V-02）。超過時は HTTP 429                             |
| C-05 | 取得した情報を、API 利用申請で申告した目的以外に使わない。第三者に譲渡・販売しない                                                             |
| C-06 | 競合サービスの提供は禁止。connpass への問い合わせを中継する汎用エンドポイントを作らない                                                        |
| C-07 | 公開ページを作ることは申請時に申告済み。申告内容と実装を一致させる                                                                             |

### 技術・費用

| ID   | 制約                                                                                                                     |
| ---- | ------------------------------------------------------------------------------------------------------------------------ |
| C-08 | TypeScript。Cloudflare（Workers + Cron Triggers、D1、Pages）                                                             |
| C-09 | 費用は Cloudflare の無料枠に収める。構成を変えるときは無料枠に収まることを確認する                                       |
| C-10 | オフライン開催の判定は、API の `prefecture` に福井・石川・富山を指定する方式による。取りこぼし・誤判定は許容する（D-11） |
| C-11 | 福井を主対象とし、石川・富山も取得する。画面上は福井と区別する                                                           |

### 公開範囲と個人情報

| ID   | 制約                                                                                                                                                                   |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| C-12 | 公開ページは一般公開。第三者由来の文字列（イベント名・場所など）は必ずエスケープして出力する                                                                           |
| C-13 | ~~RSS は認証付きで本人専用~~ → **2026-11-23 に変更: RSS は認証なしで公開する**（本人の判断。公開ページと同じ扱い）。旧決定 D-17 / D-18 / D-32 は廃止。下の R-07 を参照 |
| C-14 | 主催者名（connpass の `owner_*` の名前系フィールド）は**どこにも持たない**。D1 の列・内部の型・ログ・画面のいずれにも                                                  |

主催者名を扱わないため、個人データの保持は発生しない。個人情報保護法上の要配慮情報・決済情報・医療情報も扱わない。

## 外部の前提とリスク

本プロジェクトの努力では解消できないもの。

| ID                 | 内容                                                                                                                                                        | 扱い                                                                                                                   |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| R-01 / A-02        | API 利用審査が通らない                                                                                                                                      | **解消**（API キー発行済み）                                                                                           |
| R-02 / A-03        | 公開ページが「競合サービスの提供」に該当すると判断される                                                                                                    | 申請時に申告済み。審査結果が判断になる                                                                                 |
| R-03               | connpass API の仕様変更で収集が止まる                                                                                                                       | 境界の検証で「黙って壊れる」を「失敗として記録される」に変える（COL-11）。停止は HLT で気づく                          |
| R-04 / A-01        | レート制限の実際の値が想定と違う                                                                                                                            | 実装の最初に確認する（V-02）                                                                                           |
| R-07               | **RSS の公開が API 利用申請の申告内容と合わない**。AI-DLC の記録では、RSS を本人専用にした理由は「API 利用申請に RSS を含めていなかったため」だった（C-07） | 未解消。申請内容を確認し、必要なら connpass に利用目的の追加を届け出る。申請時に何を申告したかを本人が確認する（V-07） |
| R-05 / R-06 / A-05 | 主催者の都道府県設定漏れ・ハイブリッド開催の登録揺れによる取りこぼし                                                                                        | 許容（D-11）。`address` / `place` は保存するので、将来の補正の材料は残る                                               |
